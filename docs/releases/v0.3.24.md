# Diskvale v0.3.24 — Early preview

An open-source Windows disk explorer that helps you see what is taking up space. This preview includes the fixes after v0.3.23 and keeps the existing native Rust/egui interface and bulk NTFS reader.

## Changes

- Visible preview/version information at startup and in Scan notes; live, saved, replayed, partial and stale results are distinguishable.
- Stronger scanned NTFS/volume identity checks, runtime-only deletion authority, shared revocation and generation checks. Imported snapshots, saved-MFT replays, partial and stale results cannot authorize deletion. Shell deletion remains best effort, with concurrent-change limits and a separate permanent-deletion confirmation.
- Directory/root-owned data streams are counted once in nondeletable buckets. Incomplete stream coverage, missing attributes, stale references and out-of-volume extents are rejected explicitly.
- Snapshot saving, CSV export and comparison preparation use one bounded background job with cancellation and error reporting. Output replacement preserves previous files on exercised failures.
- Sidebar overflow pages reach empty directories. Unicode searches agree across Map, Files and Types; snapshot imports preserve case-distinct sibling names and reject exact duplicates.
- Clearer user documentation, privacy-conscious bug reports, versioned downloads and source/toolchain provenance in portable packages. No dependency updates.

## Requirements and limits

Windows 10/11 x64, whole local NTFS drives and administrator access are required. The unsigned build may trigger an unknown-publisher warning. Extract the ZIP and run Diskvale.exe; no development tools or separate Visual C++ runtime are needed. Startup waits for an explicit Scan action unless `--auto-scan` is requested.

The NTFS reader is experimental. Ordinary nonresident attribute lists currently return an unsupported-completeness error; the MFT-bootstrap reader retains its supported cases. Arbitrary folders, network shares and non-NTFS drives are unsupported. Large scans can require substantial memory. Full-volume correctness/performance parity is unestablished. Scans and Shell deletion are not atomic filesystem operations.

Snapshot schema 2 adds identities and directory-stream accounting. Compatible legacy trees remain readable after validation, with missing-accounting warnings preserved. Comparison requires matching accounting profiles; resaving does not manufacture missing streams. Unicode/case-distinct import fixes need no further schema change. All saved results remain read only.
