# Diskvale 0.3.27 — Early preview

This preview reduces NTFS scan allocation work and peak memory use, and adds separate scan-stage timings to Scan notes. The user confirmed that the extracted 0.3.27 candidate worked before authorizing publication.

## Changes since 0.3.26

- Use bounded stack storage for sector fixups and borrowed, prevalidated attribute views during bulk parsing.
- Decode filenames without a temporary UTF-16 allocation, reduce ordinary name-vector allocation and handle the common DOS alias/long-name pair without a hash set.
- Reserve checked tree capacity, move directory names into nodes and batch progress-count updates while retaining per-record cancellation.
- Reuse bounded external-list read buffers and the known bulk cursor. Every list is reread from the volume, with cursor restoration on success, error and cancellation.
- Capture bootstrap, bulk reads, parsing/validation, external-list resolution, extension merging and tree construction separately. Timings accumulate across live retries. Older snapshots remain readable through the optional timing field; schema version 2 is retained.

Dependencies, stream accounting, attribute-list/parent validation, the one-retry limit and deletion safeguards are retained.

## Validation and measured performance

Formatting, locked tests (**144 library + 7 integration tests passed; 3 opt-in tests ignored**) and strict all-target Clippy passed. All **49 MFT regressions** passed, including buffer/fixup limits, Unicode names, attribute prevalidation, hard links, retry timings, fresh external-list bytes/cursor restoration and older snapshot restrictions. Shell-deletion integrations were not enabled for this performance change.

Paired local release builds used the same Rust 1.98.1 MSVC compiler and static CRT, alternating in ABBA order. Four read-only C: scans per build reduced median elapsed time from **11.3844 s to 9.4880 s (16.66%)** and median peak working set from **2599.33 MiB to 2135.91 MiB (17.83%)**. All eight scans completed without cancellation, read errors, unknown allocations or retries. The generated 100,000-file fixture reduced median time from **62.0893 ms to 48.3009 ms (22.21%)** across 20 runs per build, with identical expected totals and zero per-file metadata queries.

These are measurements of one drive and fixture on the local compiler, not guaranteed gains on other systems or measurements of the CI executable. Live volume changes prevent an atomic full-volume accuracy comparison. No private drive captures or filenames were uploaded. See [performance validation](../scan-performance-candidate.md).

## Requirements and limits

**Windows 10/11 x64, whole-drive NTFS and administrator access are required.** This unsigned early preview may show an unknown-publisher warning. Scanning remains an experimental live metadata read, not an atomic snapshot; large scans can require substantial memory. Full-volume correctness and performance parity with other tools have not been established.

Unsupported split/compressed/sparse/encrypted attribute lists and inconsistent metadata remain explicit errors. Flat saved-MFT replay cannot supply external list clusters and never reads them from a live drive. Saved, partial and stale results cannot authorize deletion. Deletion retains best-effort identity checks and explicit confirmation; it is not atomic or race-free. See [technical details](../technical.md) and [same-drive compatibility acceptance](../ntfs-parent-test-candidate.md). Older release tags and assets are unchanged.
