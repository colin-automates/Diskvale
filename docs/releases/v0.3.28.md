# Diskvale 0.3.28 — Early preview

This preview adds scanning for external exFAT and FAT32 drives, and makes ready removable drives selectable alongside fixed disks. The user confirmed a full scan of the original E: exFAT drive on the 0.3.28 candidate before authorizing publication.

## Changes

- Scan whole local NTFS, exFAT and FAT32 drives, including supported USB and external disks. NTFS keeps its fast MFT reader; exFAT/FAT32 uses file and folder metadata without reading file contents.
- Discover drives in the background and add **Refresh drives** for newly connected devices. Selecting a drive does not automatically start a scan. The sidebar displays its filesystem.
- Keep cancellation, unreadable entries and unknown allocation explicit. Detect disappearance or a change in the volume's serial, filesystem or capacity at the end of a scan. These checks do not make a live scan atomic.
- Preserve exFAT/FAT32 snapshot accounting and keep those results read-only inside Diskvale. NTFS failures remain errors with no automatic directory fallback.
- Refresh the 30-second generated-data demo with quieter CC0 music and recorded physical mouse clicks, credited with source hashes and reproducible rendering instructions.

## Validation

`cargo fmt --all -- --check`, `cargo test --locked` (150 library tests and 7 integration tests passed), and `cargo clippy --locked --all-targets -- -D warnings` passed. Ordinary runs leave destructive integration, the saved-scan benchmark and the live-drive check ignored. Focused regressions cover engine routing, cancellation, read-only provenance, snapshot round trips, and refreshing/selecting an exFAT drive without starting a scan.

An individually selected metadata check read 68,184 files and 1,707 folders on E: in 30.02 seconds, with no read errors or unknown allocations, then cancelled at its requested time bound. The later full E: scan was **user-confirmed** on the candidate with SHA-256 `4e2bcc2af7696fe8adb80c2975224a37e7e1b9baec70f8ae8935e660ae0af645`. This is not an independent full-volume accounting comparison. A real FAT32 device and physical unplug/reconnect during scanning remain unverified. See [external-drive validation](../external-drive-candidate.md).

The production UI was inspected using generated data at 1050×700 and 1400×900. Candidate Windows resource, administrator-manifest and static-runtime checks passed. Public assets are rebuilt from the clean release commit; `BUILD_INFO.json` identifies their source, compiler and EXE checksum. No private drive captures, filenames or exports are published.

## Running and limits

Extract the portable ZIP, open Diskvale.exe, approve the administrator prompt, choose the drive and click **Scan drive**. Use **Refresh drives** for newly attached devices. Windows 10/11 x64 and a whole local NTFS, exFAT or FAT32 drive are required. No installer, development tools or separate Visual C++ runtime are needed. **This build is unsigned** and Windows may show an unknown-publisher warning; verify the published checksums.

exFAT/FAT32 scans are slower than NTFS index scans. Their file totals exclude directory allocation and filesystem metadata, and deletion is disabled for those results. Arbitrary folder scans, network shares and other filesystems remain unsupported. NTFS metadata validation, unsupported-layout errors and deletion safeguards remain enabled. Saved, partial and stale results cannot authorize deletion. Scanning and Shell deletion are not atomic operations; full-volume correctness and performance parity with other tools remain unestablished. See [technical details](../technical.md).
